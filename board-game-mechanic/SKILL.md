# 桌遊機制實作工作流程 (SKILL.md)

## 概述
本文檔總結了從實作 `dice_rolling`（骰子擲投）和 `hand_management`（手牌管理）兩個桌遊機制中學到的經驗教訓，提供了標準化的工作流程，用於未來實作其他桌遊機制場景。

## 工作流程步驟

### 1. 前期準備
1. **理解機制**：深入研究 BoardGameGeek 上的機制描述，理解核心規則和遊戲玩法
2. **設計架構**：
   - 確定需要哪些通用元件（卡牌、骰子、棋子、圖板等）
   - 設計 UI 佈局：標題、遊戲區域、控制面板、資訊面板
   - 規劃場景結構：CanvasLayer → Control → VBoxContainer/HBoxContainer

### 2. 建立場景結構
```gdscript
# 標準場景結構模板
- Node2D (主節點，附加機制腳本)
  ├── Background (ColorRect，全屏背景)
  ├── CanvasLayer (UI層)
  │   └── Control (全屏UI容器)
  │       └── VBoxContainer (垂直佈局)
  │           ├── TitleLabel (標題)
  │           ├── GameArea (遊戲區域，HBoxContainer或特定容器)
  │           ├── ControlPanel (控制面板，HBoxContainer)
  │           └── InfoPanel (資訊面板，包含統計和說明)
  └── 其他遊戲特定節點
```

### 3. 通用元件開發
1. **建立通用元件**：
   - `card.gd` / `card.tscn`：可拖放、可選中的卡牌元件
   - `dice.gd` / `dice.tscn`：可擲投、可動畫的骰子元件
   - `token.gd` / `token.tscn`：可移動的棋子元件
   - `tile.gd` / `tile.tscn`：圖板格子元件

2. **元件設計原則**：
   - 使用 `Area2D` 作為基礎，支援點擊和拖放
   - 實現標準信號：`selected`、`dragged`、`dropped`、`played` 等
   - 包含視覺反饋：懸停高亮、選中動畫
   - 使用 Tween 實現平滑動畫

### 4. 機制腳本開發
1. **腳本結構**：
```gdscript
extends Node2D
class_name [機制名稱]Demo

# 信號定義

# 匯出變數（可編輯屬性）

# 遊戲狀態變數
var 狀態變數: 類型

func _ready() -> void:
    # 初始化：獲取節點引用、連接信號、設定初始狀態
    pass

func _process(delta: float) -> void:
    # 持續更新邏輯（如果需要）
    pass

# 公開函數（遊戲邏輯）

    pass

    # 內部使用的輔助邏輯

func _on_信號名稱(參數) -> void:

    pass
```

### 5. 常見問題與解決方案

#### 5.1 警告處理
1. **未使用參數警告**：
   - 在未使用的參數前加下劃線：`_unused_parameter`
   - 範例：`func _process(_delta: float) -> void:`

2. **UI 節點錨點警告**：
   - 問題：在 `_ready()` 中設定有錨點的 UI 節點大小會產生警告
   - 解決方案：
     - 將錨點設為 `0.0`：`anchor_left = 0.0, anchor_top = 0.0, anchor_right = 0.0, anchor_bottom = 0.0`
     - 或使用 `set_deferred("size", 大小)`
     - 或使用 `call_deferred("add_child", 節點)`

3. **靜態函數呼叫警告**：
   - 問題：透過實例呼叫靜態函數
   - 解決方案：移除 `static` 關鍵字，或確保透過類別名稱呼叫

#### 5.2 動畫與視覺效果
1. **使用 Tween 系統**：
   - 創建平滑的移動、旋轉、縮放動畫
   - 設定 `set_parallel(true)` 實現並行動畫
   - 使用 `set_delay()` 實現序列動畫

2. **視覺反饋**：
   - 滑鼠懸停：輕微放大和高亮
   - 選中狀態：明顯放大和顏色變化
   - 狀態變化：漸變過渡

#### 5.3 輸入處理
1. **拖放系統**：
   - 在 `_input_event()` 中處理滑鼠點擊
   - 在 `_process()` 中更新拖曳位置
   - 在放開時檢查放置區域

2. **點擊選擇**：
   - 使用 `Area2D` 的 `mouse_entered`/`mouse_exited` 信號
   - 實現 `select()` 和 `deselect()` 方法

### 6. 測試與除錯
1. **逐步測試**：
   - 先測試基本功能，再添加動畫和效果
   - 確保所有按鈕和互動元素正常工作
   - 測試邊界情況（空牌庫、滿手牌等）

2. **警告檢查**：
   - 執行場景後檢查輸出面板的警告
   - 逐一修復所有警告
   - 目標：錯誤陣列為空

3. **功能驗證**：
   - 驗證所有遊戲規則正確實現
   - 測試使用者互動流程是否順暢
   - 確保視覺反饋清晰明確

### 7. 整合與維護
1. **更新通用元件**：
   - 將學到的最佳實踐應用到所有通用元件
   - 保持元件介面一致性

2. **更新常數檔案**：
   - 在 `constants.gd` 中添加新機制需要的常數
   - 保持顏色、尺寸、類型定義的一致性

3. **更新主選單**：
   - 將新機制添加到主選單場景
   - 更新機制列表和導航

### 8. 最佳實踐總結
1. **程式碼組織**：
   - 將相關功能分組到不同的函數中
   - 使用有意義的變數和函數名稱
   - 添加註解說明複雜邏輯

2. **錯誤處理**：
   - 使用 `get_node_or_null()` 避免節點不存在時崩潰
   - 添加適當的錯誤訊息和狀態檢查
   - 優雅處理邊界情況

3. **效能考量**：
   - 避免在 `_process()` 中進行昂貴操作
   - 使用物件池重用元件（如果需要）
   - 及時釋放不再需要的資源

4. **使用者體驗**：

   - 實現平滑的動畫過渡
   - 添加適當的音效（未來擴展）

## 新增經驗：從 grid_movement 任務中學到的教訓

### 10. 自動化工作流程建議

#### 10.1 預防性措施（減少問題發生）
1. **建立預先檢查清單**：
   - UI 錨點檢查：確保所有 Control 節點都有完整的錨點設定
   - 函數簽名檢查：避免與原生類方法衝突
   - 節點引用檢查：確保所有 `@onready` 變數都有對應的節點

#### 10.2 常見問題的深入分析
1. **非相等對立錨點警告的根源**：
   - 問題：當 ColorRect 或其他 Control 節點同時設定了錨點和大小時會產生警告
   - 根本原因：Godot 的 UI 系統期望錨點和大小設定要一致
   - 解決方案：
     - 方案 A：設定完整的錨點（0.0, 0.0, 0.0, 0.0）並使用 offset 控制大小
     - 方案 B：移除 size 設定，讓節點根據錨點自動調整大小
     - 方案 C：使用 `set_deferred()` 延遲設定大小

2. **元件程式碼中的隱藏問題**：
   - 問題：在 `tile.gd` 和 `token.gd` 中，`update_appearance()` 函數設定了 `background` 和 `highlight` 的 size
   - 發現：這些節點在場景中已經設定了完整的錨點（0,0,1,1）
   - 解決：移除程式碼中的 `set_deferred("size", ...)` 設定

#### 10.3 系統性除錯流程
1. **警告追蹤流程**：
   ```
   執行場景 → 檢查輸出警告 → 識別警告類型 → 定位問題檔案 → 分析根本原因 → 應用適當修復 → 重新測試
   ```

2. **問題分類與解決**：
   - **A 類問題**（簡單修復）：未使用參數、缺少錨點
   - **B 類問題**（中等複雜度）：函數衝突、節點引用錯誤
   - **C 類問題**（複雜）：架構問題、邏輯錯誤

### 11. 新增的最佳實踐

#### 11.1 程式碼品質保證
1. **一致性檢查**：
   - 所有 UI 節點必須有完整的錨點設定
   - 所有未使用的函數參數必須加下劃線
   - 所有節點引用必須使用 `@onready` 或適當的錯誤處理

2. **錯誤預防**：
   - 在創建新場景時使用模板
   - 在提交程式碼前運行自動檢查
   - 定期更新 SKILL.md 以反映新的經驗

#### 11.3 知識管理
1. **經驗記錄**：
   - 每個任務完成後更新 SKILL.md
   - 記錄遇到的問題和解決方案
   - 建立常見問題解答（FAQ）

2. **知識分享**：
   - 定期回顧和更新最佳實踐
   - 建立培訓材料
   - 分享成功案例和教訓

### 12. 實作案例：grid_movement 機制

#### 12.1 遇到的問題
1. **非相等對立錨點警告**：
   - NextTurnButton 節點缺少 anchor_left 和 anchor_top 設定
   - tile.gd 和 token.gd 中設定了有錨點節點的 size
   - info_panel.gd 中使用了 `set_deferred("size", default_size)`

2. **解決過程**：
   - 分析警告訊息，定位問題檔案
   - 檢查場景檔案中的錨點設定
   - 檢查程式碼中的 size 設定
   - 應用適當的修復方案

#### 12.2 學到的教訓
1. **系統性思考**：
   - 問題可能出現在多個地方（場景檔案、腳本檔案）
   - 需要全面檢查相關的所有檔案
   - 修復一個問題可能揭示其他相關問題

2. **預防勝於治療**：
   - 使用標準化模板可以避免許多常見問題
   - 建立自動化檢查可以早期發現問題
   - 定期更新知識庫可以提高團隊效率
